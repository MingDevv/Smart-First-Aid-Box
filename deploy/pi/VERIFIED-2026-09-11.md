# สิ่งที่ทำจริงบน Pi 2026-09-11 และสิ่งที่ยังไม่ได้ทดสอบ

ไฟล์อื่นใน `deploy/pi/` เขียนไว้ตอนที่ยังเข้าเครื่องไม่ได้ และวางอยู่บน **systemd system units
ที่ต้องใช้ sudo** ไฟล์นี้บันทึกสิ่งที่ **ติดตั้งและเห็นผลบนเครื่องจริงแล้ว** ซึ่งต่างออกไปในหลายจุด
เก็บทั้งสองชุดไว้: ชุดนี้คือของที่รันอยู่ ชุดเดิมคือข้อเสนอสำหรับตอนที่มีสิทธิ์ root

เครื่อง: Raspberry Pi 5 Model B Rev 1.1 · Debian 13 trixie · labwc + lightdm · ผู้ใช้ `technology`

---

## ข้อเท็จจริงของเครื่องที่เปลี่ยนแผน

### 1. ไม่มี passwordless sudo

ทุกอย่างในไฟล์นี้จึงติดตั้งใน home ของผู้ใช้ ไม่มีคำสั่งไหนต้องใช้ root
เอกสารเดิมสั่งวาง unit ที่ `/etc/systemd/system` และ policy ที่ `/etc/chromium/policies/managed/`
ซึ่งทำไม่ได้จนกว่าจะมีคนใส่รหัส

### 2. Node ของ Debian 13 ใช้ไม่ได้

`apt-cache policy nodejs` → candidate **20.19.2** แต่ `edge/controller.mjs` ใช้ `node:sqlite`
(`DatabaseSync`) ซึ่งต้อง **Node ≥ 22.5** ⇒ บริการรันไม่ได้เลยถ้าลงจาก apt

ที่ทำ: ดึง tarball ทางการของ **Node 24.21.0 LTS (linux-arm64)** ตรวจ sha256 กับ `SHASUMS256.txt`
แล้วแตกลง `~/.local/node` · เพิ่ม PATH ใน `~/.profile` · ยืนยันแล้วว่า
`require('node:sqlite')` ใช้ได้โดยไม่ต้องใส่ flag

ถอยกลับ: `rm -rf ~/.local/node` แล้วลบบรรทัด PATH ใน `~/.profile`

### 3. จอถูกตรึงไว้ที่ 1024×768 โดย kanshi ไม่ใช่ labwc

`~/.config/kanshi/config` เขียน `mode 1024x768@60.004` ทั้งที่จอรายงาน **800×480 เป็น preferred**
เปลี่ยนเป็น `800x480@60.004` แล้ว และสั่ง `wlr-randr` ให้มีผลทันที

**ค่าคาลิเบรตทัชไม่ถูกแตะเลย** — `~/.config/labwc/rc.xml` ยังถือ `calibrationMatrix` เดิม
เป็นเมทริกซ์ในพิกัดนอร์มอลไลซ์จึงไม่ผูกกับความละเอียด · **Bank ทดสอบด้วยนิ้วจริงแล้วว่าแตะตรง
ทุกจุดที่ 800×480** (2026-09-11) ทั้งที่ไฟล์คาลิเบรตบันทึกว่าวัดมาที่ 1024×768

สำรองก่อนแตะ: `~/sfab-backups/<timestamp>/` (labwc, kanshi, ไฟล์คาลิเบรต, `wlr-randr` ก่อนแก้)
และก๊อปออกนอกเครื่องไว้ที่ Mac ด้วย

ถอยกลับ:
```bash
sed -i 's/800x480/1024x768/' ~/.config/kanshi/config
wlr-randr --output HDMI-A-1 --mode 1024x768@60.004002
```

### 4. ไม่มีกล้อง

`rpicam-hello --list-cameras` → `No cameras available!` และไม่มีกล้อง USB
**อย่าตัดสินจาก `/dev/video*`** — Pi 5 มีโหนด `/dev/video19`–`/dev/video35` ซึ่งเป็น codec/ISP
ไม่ใช่อุปกรณ์จับภาพ การนับไฟล์จึงตอบผิด

หน้าตู้ตรวจด้วย `navigator.mediaDevices.enumerateDevices()` แล้วซ่อนทางสแกนแผลเอง
และใช้หน้าเลือกแผลเป็นหน้าแรกแทน ถ้าติดกล้องทีหลัง มันจะกลับมาเองโดยไม่ต้องแก้โค้ด

### 5. ⚠️ ไฟไม่พอ — ยังไม่ได้แก้

```
vcgencmd get_throttled → 0x50000    (บิต 16 = เคยไฟตก, บิต 18 = เคยถูก throttle)
dmesg: Undervoltage detected! → Voltage normalised   วนซ้ำหลายรอบภายในหนึ่งนาที
```

เกิดขึ้น**ทั้งที่ยังไม่ได้ต่อมอเตอร์เลย** Pi 5 ต้องการอะแดปเตอร์ **5V/5A (27W)**
ตรงกับเกณฑ์ในแผนที่ว่า "ถ้าไฟตกที่เคยพบยังเกิดต้องแก้ก่อนผ่านความเสถียร"
**ต้องแก้ก่อนต่อชุดขับมอเตอร์** ไม่งั้นอาการจะปนกันจนหาสาเหตุไม่เจอ

## สามอย่างที่เจอเฉพาะบนจอจริง

จำลองบนเครื่องพัฒนาไม่เจอสักอย่าง ทั้งสามทับหน้าตู้จนใช้งานไม่ได้

| อาการบนจอ | ต้นเหตุ | ที่แก้ |
|---|---|---|
| หน้าต่าง **"Unlock Keyring — Authentication required"** พร้อมคีย์บอร์ดบนจอ | Chromium ไปขอ GNOME keyring | `--password-store=basic` |
| แถบ **"Thai \| English"** ลอยทับแถบสถานะมุมขวาบน | ป้าย Translate ของ Chromium — **ใส่ `--disable-features=Translate,TranslateUI` อย่างเดียวไม่พอ** | โปรไฟล์แยก `~/.config/sfab-kiosk` ที่ seed `translate.enabled=false` |
| คีย์บอร์ดบนจอโผล่มาเอง | `/etc/xdg/autostart/squeekboard.desktop` | ทับด้วย `~/.config/autostart/squeekboard.desktop` ที่ตั้ง `Hidden=true` |

ผลพลอยได้ของโปรไฟล์แยก: คลังยากับการตั้งค่าอยู่ใน `localStorage` ของโปรไฟล์ที่หน้าตู้ใช้
การตรึงว่าเป็นโปรไฟล์ไหนทำให้มันไม่หายไปเพราะมีคนเปิด Chromium ตัวอื่น

## สิ่งที่ติดตั้งแล้วและรันอยู่

```
~/.local/node/                                   Node 24.21.0 LTS
~/sfab/                                          โค้ด (rsync มาจากเครื่องพัฒนา ไม่ได้ clone)
~/.local/share/smart-first-aid-box/commands.sqlite   สมุดคำสั่ง
~/sfab-kiosk-start.sh                            ตัวเปิด Chromium
~/.config/sfab-kiosk/                            โปรไฟล์ Chromium ของหน้าตู้
~/.config/systemd/user/sfab-edge.service         บริการ
~/.config/systemd/user/sfab-kiosk.service        หน้าจอ
~/.config/autostart/squeekboard.desktop          ปิดคีย์บอร์ดบนจอ
```

สำเนาของไฟล์ที่รันจริงอยู่ใน `deploy/pi/user-units/` — คัดลอกกลับมาจากเครื่อง ไม่ได้เขียนใหม่

ติดตั้ง:
```bash
systemctl --user daemon-reload
systemctl --user enable --now sfab-edge.service
systemctl --user enable --now sfab-kiosk.service
```

ยืนยันแล้ว: ทั้งสอง unit `active` · `GET /kiosk` = 200 · `SFAB_RUNTIME` ถูกฉีดเข้าหน้า ·
**ไม่มีโฮสต์ CDN ในหน้าที่เสิร์ฟออกมาเลย** · CSS/JS/ฟอนต์ตอบ 200 ครบ ·
แถบสถานะขึ้น "ยังไม่ได้ตั้งโหมด รอครูตั้งค่า" ถูกต้องตามกติกา fail-closed

## บทเรียนจากการบูตจริงและการไล่ปุ่ม — สามอย่างที่ "ดูเหมือนเสร็จ" แต่ไม่เสร็จ

### 1. `graphical-session.target` ตายอยู่ ทั้งที่ labwc รัน

unit ที่ `WantedBy=graphical-session.target` **ไม่ถูกปลุกเลยหลังบูต** เพราะบน Pi OS/labwc เครื่องนี้
ไม่มีใครสั่ง start target นั้นใน user manager (`systemctl --user list-units` แสดง `inactive dead`
ขณะที่ labwc รันและมี `wayland-0` แล้ว) ⇒ ย้ายไป `WantedBy=default.target` ซึ่ง active จริง
แล้วให้ unit ของจอ `ExecStartPre` รอซ็อกเก็ต wayland กับรอ `/api/local/status` ตอบเอง

**`StartLimitIntervalSec`/`StartLimitBurst` ต้องอยู่ใน `[Unit]` ไม่ใช่ `[Service]`** — วางผิด
systemd เตือนใน log แล้วเมินทิ้งเงียบๆ

### 2. `--kiosk` ไม่กันการหนีออกจากหน้าตู้

ยิงคีย์จริงด้วย `wtype` แล้ว **Ctrl+N เปิดหน้าต่าง Chromium ปกติที่เข้า Google ได้**
ทับหน้าตู้ · ต้องมี managed policy ที่ `/etc/chromium/policies/managed/`
และ **`URLBlocklist: ["*"]` ยังไม่พอ** — `chrome://*` ไม่ถูกครอบโดยปริยาย
`Ctrl+J` จึงเปิด `chrome://downloads` ได้ ต้องใส่สคีมภายในลง blocklist ด้วย

### 3. `labwc -m` = merge คอนฟิกของระบบเข้ามา

ประกาศ `<keyboard></keyboard>` ว่างใน rc.xml ของผู้ใช้ **ไม่ลบ keybind ของระบบ**
หลัง SIGHUP ดูเหมือนได้ผล แต่**พอบูตใหม่ Ctrl+Alt+T กลับมาเปิดเทอร์มินัลบนหน้าตู้ได้อีก**
ต้องทับเป็นรายปุ่มด้วย `<keybind key="C-A-t"><action name="None"/></keybind>` (20 ปุ่ม)

บทเรียนร่วมของทั้งสามข้อ: **SIGHUP/restart ผ่าน ไม่ได้แปลว่าบูตแล้วจะผ่าน** ทุกข้อนี้ผ่าน
ตอนรีโหลด แล้วพังตอนบูต

## ผลทดสอบที่ผ่านแล้ว

- **บูตใหม่ 4 รอบ กลับมาที่หน้าตู้เองทุกรอบ** — เทียบ `boot_id` ก่อน/หลังทุกครั้ง
  ถ้าไม่เปลี่ยนแปลว่าไม่ได้บูตและผลไม่นับ (รอบแรกที่ทดสอบเจอบวกปลอมแบบนี้จริง:
  สคริปต์ไม่ได้สั่ง reboot แต่รายงานว่า unit active เพราะมันรันค้างจากก่อนหน้า)
  ทุกรอบ: edge active · kiosk active · `GET /kiosk` = 200 · Chromium 11 โปรเซส
- **ไล่ปุ่มหนี 18 คอมโบหลังบูตจริง** — Esc, F11, Alt+F4, Alt+Tab, Super+D, Print,
  Ctrl+{N,T,L,J,H,P,O,W}, Ctrl+Shift+I, Ctrl+Alt+{T,W,B} ⇒ ไม่มีเทอร์มินัล
  ไม่มีหน้าต่างใหม่ ไม่หลุดออกจากหน้าตู้ unit ยัง active
- **ทัชตรงที่ 800×480** — Bank ทดสอบด้วยนิ้วจริง
